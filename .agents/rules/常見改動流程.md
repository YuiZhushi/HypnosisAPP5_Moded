# 常見改動流程

本文件說明在 HypnoOS 專案中作業系統層級（General OS）的常見開發與改動流程。

## 1. 新增一個"桌面應用" (Desktop App)

當您需要在系統中新增一個全新的桌面應用程式時，請遵循以下步驟：

1. **`types.ts`**（或對應常數層）：在 `AppMode` 列舉中添加新值。
2. **`ui/` 前端組件**：建立新組件檔案（如 `ui/{NewApp}/NewApp.tsx`），並嚴格遵守 UI 層不直接存取底層 API 的規範。
3. **`App.tsx` 或主路由**：添加 app 圖示入口與路由分發 `case`，將其整合至 OS 介面。
4. 若為**快捷動作**（不需單獨頁面），則不需要新 `AppMode`，直接在圖示點擊事件中執行對應操作。

## 2. 條件解鎖式的 APP 新增 (Condition-unlocked App addition)

當新增的桌面應用需要滿足特定條件才能解鎖時，請遵循以下步驟：

1. **註冊 APP 與解鎖條件**：在 `backend/` 層註冊新的 APP，並在 `constants/` 定義 APP 的唯一識別碼與解鎖條件（例如：特定事件觸發、特定好感度或變數條件）。
2. **邏輯判斷**：解鎖條件的檢查邏輯必須實作於 `backend` 或 `shared/mvuBridge`，**嚴禁**在 `ui` 層進行業務邏輯判斷。
3. **UI 渲染**：透過 MVU 架構將解鎖狀態同步至 UI 層，React 組件根據狀態決定是否渲染該 APP 圖示。

## 3. 新增一種消息構造協議 (Message Protocol)

基於最新的 AI 資料處理標準流程（Pipeline），新增或修改消息發送的協定請遵守以下步驟：

1. **準備階段 (APP 層)**：在專屬的 APP `constants/` 或 `backend/` 下，定義該協議所需的提示詞模組（Prompt Modules）、變數佔位符與格式。
2. **構造發送參數**：實作專屬的消息構造函數（例如 `buildHypnosisSendMessage`），將情境參數轉化為 Pipeline 可接受的 `AiRequestParams` 格式。
3. **烹飪階段 (Shared 層)**：交由 `@src/催眠APP前端/shared/ai/aiRequestPipelineService.ts` 統一處理拼接、發送請求與接收，**嚴禁**在 UI 組件內手動拼接字串。
4. **擺盤階段 (APP 層)**：在收到 Pipeline 回傳的資料後，於 APP 後端進行解析，若需要更新世界書或傳送聊天訊息，請呼叫對應的 Shared 服務（如 `WorldBookRepository` 或 `ChatTransport`）。

## 4. 遷移大型字串需求 (String Migration)

如果有遷移大型字串的需求，在程式碼需要搬遷的對應部分進行標記與標示。在任務的其他部分都結束後，再讓用戶後續手動搬遷，避免因為大型字串造成的搬遷困難與 Token 過度消耗問題。
