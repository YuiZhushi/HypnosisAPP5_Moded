# 酒館變量交互規則

酒館變數（Variables）可用於持久化地儲存前端介面或腳本的資料。在 HypnoOS 的新架構中，變數的讀寫有著嚴格的規範。

## 1. 變數生命週期與類型

開發時必須清楚區分以下三種變數的生命週期：

1. **Runtime 變數**：僅存在於 iframe 記憶體中（如 React Component State 或一般的 JS 變數），重新載入即消失，無法持久化。
2. **聊天變數 (Chat Variables)**：綁定在某角色卡的某個聊天檔案上（`{type: 'chat'}`）。在單一對話內保持跨樓層通用，適合儲存全域狀態（如系統設定、玩家資源等）。
3. **MVU 變數 (Message Variables)**：綁定在特定樓層上（`{type: 'message', message_id: 'latest'|number}`）。在不同樓層、不同 Swipe 中獨立儲存，並會自動繼承上一樓層的資料。適合儲存與時間軸強相關的資料（如角色狀態、任務進度）。

## 2. 嚴格的存取規範

在新的領域驅動分層架構下，**絕對禁止 UI 層直接操作底層變數**。

### 2.1 UI 層 (前端介面)

* **禁止**：直接調用酒館助手的 `getVariables`、`updateVariablesWith` 或 `replaceVariables`。
* **正確做法**：UI 層若需要讀取或修改變數，必須呼叫 `backend/` 提供的 API（例如 `DataService.getUserData()`）。
* **例外（UI 刷新觸發器）**：前端 UI 組件可以訂閱 `Mvu.events.*`（例如 `Mvu.events.VARIABLE_UPDATE_ENDED`）作為畫面刷新的觸發器，但**仍不可直接操作**底層變數。

### 2.2 Backend 層 (業務邏輯)

* **職責**：負責處理 UI 層傳來的意圖（Intent），進行業務邏輯判斷後，再調用 `shared/` 層的服務進行變數的讀寫。
* **正確做法**：透過 `shared/store/*` 存取聊天變數，或透過 `shared/mvu/mvuBridge.ts` 存取 MVU 變數。

### 2.3 Shared 層 (基礎設施)

* **職責**：統一封裝對酒館底層變數的讀寫操作，並確保資料的一致性與序列化（避免並發衝突）。
* **範例**：`mvuBridge.ts` 封裝了對 `Mvu` 全局對象的存取，並提供了 `enqueueMvuWrite` 來確保寫入安全。

## 3. 資料與持久化契約參考

為了確保資料結構的正確性，所有寫入酒館變數的資料都應該使用 Zod 進行格式定義與驗證。

* **用戶資源（`UserResources`）→ 聊天變數 `系统`**：
  * `mcEnergy` -> `系统._MC能量`
  * `mcEnergyMax` -> `系统._MC能量上限`
  * `mcPoints` -> `系统.当前MC点`
  * `totalConsumedMc` -> `系统._累计消耗MC点`
  * `money` -> `系统.持有零花钱`
  * `suspicion` -> `系统.主角可疑度`

* **私有持久化 store（`系统._hypnoos` → `PersistedStore`）**：
  包含 `debugEnabled`, `sessionEndVirtualMinutes`, `sessionEndAtMs`, `subscription`, `features`, `achievements` / `quests` 等。
  * **寫入規則**：所有對 store 的寫入必須透過後端 API（如 `updateStoreWith(...)`）完成，寫入後自動調用 `MvuBridge.syncPersistedStore(...)` 做 MVU 同步。
