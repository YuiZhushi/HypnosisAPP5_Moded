# app_develop 技能指引

在開發 HypnoOS 的新桌面應用（APP）或功能模組時，為了保證代碼的健壯性與可維護性，請遵守以下基於 **React + TailwindCSS** 的開發規範。

---

## 1. 開發期架構與 UI 資料流 (ui -> MockAPI)

目前專案處於 MockAPI 開發與快速迭代期：
* **Mock 數據隔離**：所有的靜態預置資料與運行時變數在 iframe 載入時就已被加載至記憶體中。
* **資料流向**：**UI 層不直接觸碰任何靜態資料或變數，而是統一通過 MockAPI 接口來存取數據。**
* **依賴關係**：`ui` -> `MockAPI`。嚴禁 UI 組件內部直接調用底層酒館 API 或直接操作本地存儲。

---

## 2. 開發新功能時的步驟 (Mock 導向)

當您需要為特定 APP（如催眠、角色編輯器、成就任務）新增或修改功能時，遵守以下流程：

1. **更新 Mock 數據與接口**：
   * 在 MockAPI 的數據庫與接口中註冊新 App 或新功能（如新催眠 Feature 的 id、價格、解鎖狀態；新任務的 `questDb` 配置）。
   * 在 MockAPI 內實作對應的狀態變更邏輯（如購買、啟用、解鎖、扣款）。
2. **在 UI 組件中調用**：
   * UI 組件僅透過調用 MockAPI 來獲取或修改資料。
   * 根據 MockAPI 回傳的狀態來決定 UI 渲染（如是否解鎖、是否可見）。
3. **資料結構修改規則**：
   * **預設「不進行 fallback」**，直接使用新資料。這樣能讓迭代間的 bug 暴露出來，利於排查重構或擴充是否成功。

---

## 3. UI 佈局與 Iframe 適配

HypnoOS 運行在 iframe 且有固定比例的模擬框中，UI 開發需符合以下硬性限制：
* **優先使用 TailwindCSS 原子類**：間距與字體大小已被 `@theme` 覆寫為基於 `cqw` (Container Query Width) 與 `clamp` 的公式，會自動實現流暢縮放。
* **絕對禁止使用 `vh` / `vw` 單位**：這會受宿主容器高度影響導致排版崩潰。必須使用百分比（`w-full h-full`）搭配 `aspect-ratio` 控制。
* **避免撐高容器**：不要使用會撐高外層容器的屬性（如 `min-height`），具體滾動區域使用 `overflow-y-auto` 控制。

---

## 4. 生命週期與事件

* **載入初始化**：禁止使用 `DOMContentLoaded`，必須使用 jQuery 的 `$(() => { ... })`。
* **卸載與清理**：所有清理工作（如取消監聽、銷毀動態掛載元素）必須使用 `$(window).on('pagehide', ...)`，**禁止使用 `'unload'` 事件**。
* **日誌規範**：統一使用 `loggerService.ts` 輸出日誌，並加上 `[HypnoOS]` 前綴。

---

## ✅ 開發前審查清單 (Checklist)

- [ ] **數據流隔離**：確認 UI 組件是否僅與 MockAPI 交互，**沒有**直接接觸靜態數據或原始變數？
- [ ] **不 fallback 預設**：資料結構有異動時，確認是否預設不 fallback 直接載入新資料？
- [ ] **佈局適配**：確認**沒有使用**任何 `vh`/`vw` 單位？
- [ ] **生命週期**：初始化與清理是否正確使用 `$(() => {})` 與 `pagehide`？
