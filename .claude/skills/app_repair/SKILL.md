# app_repair 技能指引

本 Skill 指導如何在 HypnoOS（基於 React + Tailwind v4 模擬手機 iframe 專案）中有效地診斷與修復各種錯誤，並規範修補行為。

---

## 1. 核心修復原則

1. **先觀察，後修改**：先使用閱讀工具全面理解原有代碼（如 `ui/`、`database/`、`models/` 或是 `shared/`），理清其依賴關係，**禁止盲目覆寫檔案**。
2. **遵循數據流隔離**：修復資料流錯誤時，確認 UI 層只調用 MockAPI，而沒有直接讀取靜態常數（`staticData/`）或原始變數。修復落點應在 MockAPI 的數據庫與接口中。
3. **預設不 fallback**：在修復涉及資料結構變更的問題時，**預設「不進行 fallback（不相容舊資料），直接使用新資料」**，讓迭代間的 bug 暴露，徹底驗證修補是否成功。
4. **適配 UI 排版**：排版崩潰問題優先檢查是否誤用了 `vh`/`vw` 單位。若有，改用百分比或外層 `w-full h-full` 搭配比例控制。選單遮擋檢查 `z-index` 及父容器的定位屬性。
5. **修正生命週期**：若有初始化或清理失效的問題，確認沒有使用 `DOMContentLoaded`（改用 `$(() => {})`）及 `'unload'` 事件（改用 `'pagehide'`）。

---

## 2. 診斷排查步驟

當接到修復需求時，請按以下步驟排查：

```
收到修復任務 
  └─ 1. 理清錯誤源頭（是 UI 組件邏輯，還是 MockAPI 數據問題？）
  └─ 2. 檢查資料流向（UI 是否只跟 MockAPI 交互？變數是否有被正確寫回 Mock 庫？）
  └─ 3. 檢查 UI 排版與適配（是否有寫死的 Pixel 或使用 vh/vw？）
  └─ 4. 檢查生命週期（初始化 $(() => {}) 與 pagehide 是否完整？）
  └─ 5. 進行最小化精準修補
  └─ 6. 構建驗證（倉庫根目錄 pnpm build:dev）
```

---

## ✅ 修復審查清單 (Checklist)

- [ ] **依賴方向**：修復後是否仍保持單向依賴（UI 僅依賴 MockAPI / Shared，無循環引用）？
- [ ] **不 fallback**：若資料結構有異動，是否預設不進行 fallback？
- [ ] **Iframe 適配**：確認沒有在修補中寫死 Pixel 或是引入 `vh`/`vw`？
- [ ] **生命週期**：初始化與清理是否正確使用 `$(() => {})` 與 `pagehide`？
- [ ] **日誌規範**：日誌輸出是否統一使用 `loggerService.ts` 並包含 `[HypnoOS]` 前綴？
