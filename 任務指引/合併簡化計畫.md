# 合併簡化計畫

## 目標

減少不必要的抽象層級，將調用鏈從 4-5 層減少到 2-3 層，提升代碼可維護性。

---

### Phase 1：移除空殼 Domain Service

| 序號 | 動作 | 說明 |
|------|------|------|
| 1.1 | 合併 `calendarService.ts` + `calendarEventImpl.ts` → `calendarService.ts` | 將實際邏輯移入 domain 層 |
| 1.2 | 合併 `featureService.ts` 邏輯到 dataService.ts | feature 功能簡單，直接在 dataService 實現 |
| 1.3 | 合併 `subscriptionService.ts` 邏輯到 dataService.ts | 訂閱邏輯直接實現 |
| 1.4 | 合併 `customHypnosisService.ts` 邏輯到 dataService.ts | 自訂催眠邏輯直接實現 |
| 1.5 | 合併 `achievementQuestService.ts` + `achievementQuestImpl.ts` + `achievementQuestCore.ts` → `achievementQuestService.ts` | 三個文件合併為一 |

**刪除的文件**：
- `services/domain/calendarService.ts`

### Phase 3：重構 dataService.ts

| 序號 | 動作 | 說明 |
|------|------|------|
| 3.1 | 模組化依賴注入 | 將 300+ 行的依賴注入代碼提取到獨立模組 |
| 3.2 | 分離服務實例化 | 創建 `services/instances.ts` 集中管理 |

**預期結果**：
- `dataService.ts` 從 844 行減少到 ~300 行
- 依賴注入邏輯集中管理
- 更容易理解和維護

### Phase 4：層級重新定義

**重構後的層級結構**：

```
src/催眠APP前端/services/
├── dataService.ts        # Facade（精簡後）
├── mvuBridge.ts          # MVU 橋接
├── access.ts             # 權限控制
├── store/                # Store 管理
│   └── storeGateway.ts
├── helpers/              # 工具函數
│   └── *.ts              # 合併後的 helper
├── constants/            # 常數定義
│   └── features.ts       # 合併後
└── usecases/             # 業務用例（保留）
    └── hypnoAppUsecaseService.ts
```

**調用鏈變化**：

| 重構前 | 重構後 |
|--------|--------|
| 組件 → DataService → Domain → Usecase → Helper → Store | 組件 → DataService → Usecase → Helper → Store |
