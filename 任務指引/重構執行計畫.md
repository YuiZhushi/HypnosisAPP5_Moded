# 重構執行計畫：終極解耦與模組化 (2026-04 最新版)

基於最新的架構分析報告，本專案存在顯著的「God Object (characterDataService.ts)」、「依賴倒置 (dataService.ts)」與「邏輯分散 (Worldbook API 操作)」問題。

為確保重構過程安全且易於驗證，實作將拆分為四個階段。請遵循此計畫逐步執行，並在每階段完成後更新 `cline_progress.md`。

---

## 🚀 階段一：統一 Worldbook 存取層與抽象化 (Repository Pattern)

**目標**：解決 `worldBookService.ts` 與 `characterDataService.ts` 中重複呼叫 iframe 全域 API 的問題，將世界書 I/O 收斂。

- **步驟 1-1：建立 Repository 層**
  - 新增 `src/催眠APP前端/services/repositories/worldBookRepository.ts`。
  - 將 `getCharWorldbookNames`、`getWorldbook`、`updateWorldbookWith` 等全域函數的宣告與呼叫封裝至此。
  - 提供高階 API，例如 `getCurrentCharacterWorldbook()`、`findEntryByName()`、`upsertEntry()` 等。

- **步驟 1-2：重構 `worldBookService.ts`**
  - 移除檔案內的全域 API 呼叫，改用 `worldBookRepository`。
  - 清理不再需要的輔助函數，專注於 `checkAndEnsureEntry` 與人物列表初始化的業務邏輯。

- **步驟 1-3：重構 `characterDataService.ts` (部分)**
  - 將其內部的 `loadCharacter` 與 `saveCharacter` 中讀寫世界書的邏輯，改為呼叫 `worldBookRepository`。

---

## 🚀 階段二：拆解 God Object (`characterDataService.ts`)

**目標**：解決 `characterDataService.ts` 臃腫 (1100+行) 且違反 SRP 的問題，將底層解析與高層業務分離。

- **步驟 2-1：抽離 AST 與 YAML 轉換器**
  - 新增 `src/催眠APP前端/services/helpers/astYamlHelper.ts` (或類似名稱)。
  - 將 `yamlToTree`、`treeToYaml`、`parseSectionYamlToNodes`、`serializeSectionNodesToYaml` 移入。

- **步驟 2-2：抽離 EJS 行為分支解析器**
  - 新增 `src/催眠APP前端/services/helpers/behaviorBranchHelper.ts`。
  - 將 `parseBehaviorBranchesFromRaw`、`parseEjsBranches`、`serializeBehaviorBranches`、`sortBehaviorBranches`、`validateBehaviorBranches` 移入。

- **步驟 2-3：抽離預設模板與常數**
  - 新增 `src/催眠APP前端/services/constants/characterDefaults.ts`。
  - 將 `buildDefaultGlobalRulesNodes`、`buildDefaultBehaviorBranchNodes`、`DATA_KEY_TO_SECTION`、`SECTION_LOCKED_KEYS` 移入。

- **步驟 2-4：瘦身 `characterDataService.ts`**
  - 經過上述抽離後，該檔案應僅保留 `loadCharacter` 與 `saveCharacter` 的核心組裝邏輯，做為存取角色資料的 Facade / Service。

---

## 🚀 階段三：消除 `dataService.ts` 的依賴倒置與過度封裝

**目標**：解決 Facade 實作核心邏輯並將其注入 Manager 的反向依賴問題。

- **步驟 3-1：遷移核心資源邏輯**
  - 將 `dataService.ts` 中的 `getUserDataCore`、`updateResourcesCore` 遷移至 `resourceManager.ts` 中，或建立獨立的 `systemCoreManager.ts` 負責這些基礎共用邏輯。
  - 將 `getSystemClockCore` 與 `syncSubscriptionTierLabel` 遷移至 `resourceManager.ts` 或 `calendarManager.ts`。

- **步驟 3-2：重構 Manager 的初始化**
  - 移除 `dataService.ts` 中實例化 Managers 時注入的龐大 `deps` 物件。
  - Managers 應該直接匯入所需的共用 Helpers 或 Store Gateway 介面，或是透過更輕量的 Context 進行依賴注入。

- **步驟 3-3：極致瘦身 `dataService.ts`**
  - `dataService.ts` 應退化為一個純粹的轉發站，只負責 export 各 Manager 提供的方法。

---

## 🚀 階段四：重新命名與清理

**目標**：解決命名冗長與混淆的問題。

- **步驟 4-1：簡化 AST 處理服務命名**

  - 將 `characterCompletionAppMergeService.ts` 重新命名為 `astMergeService.ts` (或 `helpers/astMerge.ts`)。
  - 修改 `types.ts` 中對應的 `CharacterCompletionApp*` 長型別名稱（例如改為 `AstDiffProposal`, `AiPatchResult` 等）。

- **步驟 4-2：更新引用路徑**
  - 搜尋 `components/CharacterEditor/` 下的所有組件，將對上述檔案與型別的引用路徑及名稱更新。

- **步驟 4-3：最終驗證**
